## 4. Anomalies, failed runs, open problems

1. **Pre-commit hang (resolved, cause likely but not proven).** One commit attempt for 0.5 stalled for more than 5 minutes inside `test_run_noop`: a `pharmachecked.run` subprocess never exited. MLflow 3.17 sends usage telemetry and flushes it over the network at exit. Telemetry is now disabled (`MLFLOW_DISABLE_TELEMETRY`) in the tracker and the tests. The next commit and all later ones passed the hook in about 75 s. The hang was not reproduced, so the cause is not confirmed.
2. **Dirty-flag bug (fixed in 9142d0e).** The first version ignored all untracked files, so a run with new, uncommitted source modules was recorded as clean. Now only untracked paths under `results/` are ignored.
3. **Embedding width bug (fixed before commit).** The first backbone table used timm `num_features` for MobileNetV3 (960), but the pooled output is 1280. The table now reads the width from the forward pass.
4. **Relative output path bug (fixed in 8aa5628).** MLflow's artifact URI failed for relative `paths.mlruns_dir` overrides. Covered by a test now.
5. **CLIP embedding is the projected 512-d image embedding** (`encode_image`). The tower's pre-projection width is 768. Which one the E1 head uses is decided in 2.3.
6. **Throughput varies on this laptop.** A scratch benchmark before step 0.7 measured some models up to roughly 20% faster or slower than the committed table (thermal and power state). GPU-hour estimates will use the GPU PC's own `bench_gpu-pc.md` and the fold-0/seed-0 timing that CLAUDE.md §12 requires.
7. **Kaggle folder structure.** A read-only look suggests the Kaggle source's shipped `train/`, `val/` and `test/` subfolders duplicate the images in `dataset/Fake` and `dataset/Real`. Counts will be reported by the PLAN 1.1 inventory; exact-duplicate collapse (1.3/1.4) handles it.
8. Two Python 3.13 builds exist on the laptop (`py -3.13` → 3.13.5, used for `.venv`; `python` on PATH → 3.13.14). This is harmless; `env.json` records the version per run.
9. `scripts/pack_results.py` was run once with no matching runs, as a check. It wrote a bundle holding only the benchmark table to `bundles/` (git-ignored), and `unpack_results.py --verify-only` accepted it.
