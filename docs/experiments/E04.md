# E04 · Multi-branch model

Written before the experiment runs (PLAN 3.4). It runs after E5 in the Phase 3 GPU kit. The
Results section is added afterwards.

## Question

Do a local (tile) branch, a frequency branch and a packaging-type router add anything over the
global-only model, and which design choices matter?

## Hypothesis

In the development pool, AUROC is at the ceiling, so ablations are expected to be
indistinguishable from the full model. The frequency branch has access to JPEG block artifacts
present only in authentic images (ADR-005, ADR-017); if it relies on them, the external block
should show it.

## Model (ADR-015, ADR-017)

448 px input; global branch = image resized to 224 px through EfficientNetV2-S + LoRA rank 8;
local branch = 2×2 tiles of 224 px through the same backbone, gated-attention MIL; frequency
branch = log FFT magnitude + 8×8 block-DCT AC energy of the grayscale input → 4-block CNN →
256-d; gated fusion to 256-d; router over blister/packaging/both/other (ADR-009) on the global
embedding with auxiliary cross-entropy weight 0.3 (not applied to MixUp/CutMix batches, whose
packaging types are mixed; `not_a_drug` images ignored, ADR-009); 4 expert heads mixed by router
probabilities. Training: the E5 recipe, batch 8, backbone LR multiplier 1.0.

## Arms (15 runs each)

| Arm | Change from `full` |
|---|---|
| `full` | none |
| `no-local` | no local branch |
| `no-frequency` | no frequency branch |
| `no-router` | single head, no router |
| `concat` | concatenation fusion instead of gated |
| `separate-local` | separate (unshared) backbone copy for the tiles |
| `tiles4-896` | 896 px input, 4×4 tiles (gradient checkpointing for memory) |
| `hard-routing` | argmax expert head instead of the probability mix |

The global-only reference is the E5 arm that carries the chosen recipe (`results/pipeline/e04_arms.json`).

## Pre-registered rule for the final model (applied at CHECKPOINT 3, on the laptop)

Comparisons are paired DeLong tests on pooled OOF predictions, Holm-corrected within E4, with
"significantly" meaning corrected p < 0.05 and a bootstrap CI excluding 0 (CLAUDE.md §5).

- **Branches.** The local branch, frequency branch and router are kept only if `full`
  significantly beats the corresponding `no-*` arm. Otherwise they are dropped.
- **Design choices.** Concat fusion, the separate local backbone, 4×4 tiles and hard routing
  replace the default only if they significantly beat `full`.
- **Fallback.** If no branch is kept, the final model is the global-only reference.

The final model is used in Phase 4 as the "full E4 model" comparison model.
