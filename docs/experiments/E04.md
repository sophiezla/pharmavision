# E04 · Multi-branch model

Written before the experiment runs (PLAN 3.4). It runs after E5 in the Phase 3 GPU kit. The
Results section is added afterwards.

## Question

Do a local (tile) branch, a frequency branch and a packaging-type router add anything over the
global-only model, and which design choices matter?

## Hypothesis

In the development pool, AUROC is at the ceiling, so ablations are expected to be
indistinguishable from the full model. The frequency branch has access to JPEG block artifacts
present only in authentic images (ADR-005, ADR-017); if it relies on them, the external block
should show it.

## Model (ADR-015, ADR-017)

448 px input; global branch = image resized to 224 px through EfficientNetV2-S + LoRA rank 8;
local branch = 2×2 tiles of 224 px through the same backbone, gated-attention MIL; frequency
branch = log FFT magnitude + 8×8 block-DCT AC energy of the grayscale input → 4-block CNN →
256-d; gated fusion to 256-d; router over blister/packaging/both/other (ADR-009) on the global
embedding with auxiliary cross-entropy weight 0.3 (not applied to MixUp/CutMix batches, whose
packaging types are mixed; `not_a_drug` images ignored, ADR-009); 4 expert heads mixed by router
probabilities. Training: the E5 recipe, batch 8, backbone LR multiplier 1.0.

## Arms (15 runs each)

| Arm | Change from `full` |
|---|---|
| `full` | none |
| `no-local` | no local branch |
| `no-frequency` | no frequency branch |
| `no-router` | single head, no router |
| `concat` | concatenation fusion instead of gated |
| `separate-local` | separate (unshared) backbone copy for the tiles |
| `tiles4-896` | 896 px input, 4×4 tiles (gradient checkpointing for memory) |
| `hard-routing` | argmax expert head instead of the probability mix |

The global-only reference is the E5 arm that carries the chosen recipe (`results/pipeline/e04_arms.json`).

## Pre-registered rule for the final model (applied at CHECKPOINT 3, on the laptop)

Comparisons are paired DeLong tests on pooled OOF predictions, Holm-corrected within E4, with
"significantly" meaning corrected p < 0.05 and a bootstrap CI excluding 0 (CLAUDE.md §5).

- **Branches.** The local branch, frequency branch and router are kept only if `full`
  significantly beats the corresponding `no-*` arm. Otherwise they are dropped.
- **Design choices.** Concat fusion, the separate local backbone, 4×4 tiles and hard routing
  replace the default only if they significantly beat `full`.
- **Fallback.** If no branch is kept, the final model is the global-only reference.

The final model is used in Phase 4 as the "full E4 model" comparison model.

## Metrics, tables, figures

As E1, plus mean gate weight per branch per packaging type (from OOF outputs).
`results/tables/e04_ablation`, `results/figures/e04_gate_weights_by_packaging` (PLAN 3.7).

## Results

120 runs (8 arms × 15) on data v2 with the default recipe (E5 kept no component), Phase 3 kit
(commit 0d31953), 0 failures. Tables: `results/tables/e04_summary.{csv,md}` (includes the
global-only reference `e05:efficientnetv2-s/default`), `e04_pairwise.md` (vs the best pooled
AUROC) and `e04_vs_reference.md` (every arm vs `full`, Holm-corrected DeLong, ΔAUROC / ΔECE /
Δlog-loss CIs; this is the `e04_ablation` table of PLAN 3.7). Exploratory external AUROC:
`results/tables/external_auroc_exploratory.md`.

Not produced: `e04_gate_weights_by_packaging`. The run folders do not store gate weights
(`oof_predictions.csv` has the standard columns only) and the E4 checkpoints are on the GPU PC,
so the figure needs a prediction pass over the saved `full` checkpoints. Decided 2026-10-19
(option a): a GPU-PC kit runs `scripts/predict_branch_outputs.py --exp e04 --model multibranch
--variant full`, which reloads each `best.pt` (no training), writes `branch_outputs.csv` (gate
weights, router probabilities) into each run folder and checks the re-predicted probabilities
against `oof_predictions.csv`. Back on the laptop, `scripts/gate_table.py` builds
`results/tables/e04_gate_weights.{csv,md}` and `scripts/make_figures.py --exp e04` the figure.

## Findings

- Applying the pre-registered rule: `full` does not significantly beat `no-local`,
  `no-frequency` or `no-router` (Holm p ≥ 0.887 for all three), so no branch is kept. No design
  variant (concat, separate-local, tiles4-896, hard-routing) significantly beats `full`. Under
  the fallback the final model is the global-only reference, EfficientNetV2-S + LoRA r8 with the
  default recipe (ADR-020, accepted 2026-10-19).
- `full` is also indistinguishable from the global-only reference on pooled AUROC (`e04_vs_reference.md`).
- External block (descriptive, ADR-005): every multi-branch arm except `no-local` has Mendeley
  specificity between 0.246 and 0.453, against 0.867–0.877 for the global-only reference, and higher
  Split E recall (`e04_summary.md`). Removing the frequency branch gives the lowest Mendeley
  specificity, so the hypothesis that the frequency branch drives the external behaviour is not
  supported by this table; the local (tile) branch is the ablation that moves it most.
- Exploratory, threshold-free (`results/tables/external_auroc_exploratory.md`, not pre-registered, ADR-005): run-averaged external AUROC is 0.851 [0.815, 0.884] for the global-only reference and 0.529 [0.470, 0.589] for `full`; among the multi-branch arms only `no-local` (0.747) and `no-router` (0.645) have CIs above 0.5, and `tiles4-896` is below it (0.362).
