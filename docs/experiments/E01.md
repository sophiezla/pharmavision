# E01 · Baseline ladder

Written before the experiment runs (PLAN 2.5). The Results section is added afterwards.

## Question

How well do standard model families separate counterfeit from authentic packaging in the
development pool, and how much of that holds on the external sets? The families run from
handcrafted features through CNNs and ViTs to foundation models.

## Hypothesis

Pretrained backbones beat handcrafted features and the from-scratch CNN on pooled OOF AUROC.
In-distribution AUROC may saturate near the ceiling for many models, because acquisition cues
separate the classes in this pool (ADR-005). If so, the external block (Mendeley specificity,
Split E recall) is what separates the models. No direction is predicted among the pretrained
tiers.

Pretrained weights follow ADR-003. The CLIP embedding is the projected 512-d image embedding
for fine-tuning, linear probe and zero-shot alike.

## Fixed settings

- Protocol: CLAUDE.md §5. Splits v1: 5 outer folds × seeds 0, 1, 2; inner train/val/cal; OOF
  predictions; locked test set untouched.
- 224 px; default augmentation recipe (`configs/data/transforms.yaml`); eval = resize + center
  crop.
- Training (`configs/train/default.yaml`): AdamW, head LR 3e-4, weight decay 0.05, 1-epoch
  warm-up then cosine, max 30 epochs, early stopping on val AUROC (patience 7), gradient
  clipping 1.0, batch 32, bf16 autocast on the GPU.
- Decision threshold: Youden on the fold's val split.
- Hardware: the GPU PC (RTX 5060, 8 GB; ADR-010) for the torch arms; the laptop CPU for tier 1.

## Metrics

- Primary: pooled OOF AUROC with a 95% bootstrap CI.
- Secondary: AUPRC, sensitivity at 95% specificity, balanced accuracy, macro-F1, ECE, Brier
  (per run mean ± std and pooled).
- External block (ADR-005): run-averaged specificity on `mendeley_split_c` and
  `mendeley_split_d`, recall on Split E, each with a CI.
- Cost: parameters, trainable parameters, training minutes per run, peak GPU memory.

## Hyperparameter search (PLAN 2.7)

After the default-settings runs, the best model of each trainable tier (1, 2, 3, 4, 5) gets an
Optuna search (≤ 30 trials, fold 0 inner val only) over LR, weight decay and the backbone LR
multiplier; XGBoost gets depth/learning rate/estimators. The chosen settings are frozen in the
model config, and that model re-runs the full protocol as a `tuned` variant.

## GPU-hour estimate

Measured, not guessed (CLAUDE.md §12). A timing batch runs fold 0 / seed 0 of every GPU arm on
the GPU PC first. The estimate is (time of that run) × (number of runs) per arm. It is reported,
and runs over 4 GPU-hours wait for approval (Rule 7).
