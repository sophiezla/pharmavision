# E02 · Adaptation strategy

Written before the experiment runs (PLAN 2.9). It runs automatically after E1 in the Phase 2
GPU kit (ADR-013). The Results section is added afterwards.

## Question

For the two best E1 backbones, how much of each backbone needs to adapt? The strategies range
from training only a linear head to fine-tuning everything, and include low-rank adapters.

## Hypothesis

No direction is predicted. In-distribution AUROC is expected to saturate for most strategies
(ADR-005), so the comparison rests on log-loss and calibration, the external block, and cost
(trainable parameters, minutes per run).

## Backbones

The two best distinct pretrained backbones of E1 by the pre-registered ranking (E01.md: pooled
OOF AUROC, ties → pooled OOF log-loss; development pool only). They are chosen by the
pipeline and recorded in `results/pipeline/e01_decisions.json`.

## Arms (per backbone)

| Arm (variant) | What trains | Source |
|---|---|---|
| `lp` | head only, backbone frozen in eval mode | E1 run when E1 ran it (DINOv2, CLIP); otherwise new in E2 |
| `last2` | last 2 blocks/stages + final norm + head; backbone LR × 0.1 | new |
| `ft` | everything; backbone LR × 0.1 | E1 run |
| `lora8` | LoRA rank 8 adapters + head; base weights and batch-norm statistics frozen; adapters at the head LR (backbone LR multiplier 1.0) | new |
| `lora16` | same with rank 16 | new |

LoRA (Hu et al., 2022, via `peft` 0.21.2), alpha = 2 × rank, no dropout. Target modules:

| Backbone | LoRA targets |
|---|---|
| ViT-B/16, Swin-T, DINOv2-S/B | attention `qkv` projections (PLAN 2.10) |
| CLIP ViT-B/16 | fused attention (`attn`: input and output projections) |
| ConvNeXt-T | block MLP `fc1`, `fc2` (no attention layers) |
| ResNet-50 | 1×1 convolutions `conv1`, `conv3` (no attention layers) |
| EfficientNetV2-S | pointwise convolutions `conv_pw`, `conv_pwl` (no attention layers) |

The plan specifies LoRA on attention `qkv`. Attention-free CNNs have no such layers, so their
pointwise layers are the closest analogue. This adaptation applies only if a CNN is among the
two backbones.

## Fixed settings

The E1 protocol and default training recipe (`configs/train/default.yaml`) are untuned, so
every strategy starts from the same settings. Selection follows ADR-012. Strategies taken from
E1 are the same configuration under the same protocol and are not re-run.

E1 timing batch (`results/tables/e01_timing.md`).
