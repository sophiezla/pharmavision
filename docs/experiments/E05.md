# E05 · Training recipe

Written before the experiment runs (PLAN 3.1). It runs first in the Phase 3 GPU kit, and its
decision is applied automatically (ADR-013). The Results section is added afterwards.

## Question

Does any single change to the default training recipe improve the global-only model?

## Hypothesis

With pooled OOF AUROC near the ceiling (E1, E2), no component is expected to meet the protocol's
improvement criterion. A null result keeps the default recipe.

## Model

Global-only: EfficientNetV2-S with LoRA rank 8, backbone LR multiplier 1.0 (ADR-015).

## Arms (15 runs each)

| Arm | Change from the default recipe |
|---|---|
| `default` | none (re-run inside E5, so every comparison uses the same data version) |
| `hflip` | horizontal flip, p = 0.5 |
| `colorjitter` | brightness/contrast/saturation 0.4, hue 0.1 (replaces the default jitter) |
| `randaugment` | RandAugment, 2 ops, magnitude 9 |
| `mixup` | MixUp, alpha 0.2 |
| `cutmix` | CutMix, alpha 1.0 |
| `focal` | focal loss, gamma 2, class-balanced alpha (share of authentic in the training split) |
| `smoothing` | label smoothing 0.1 |
| `supcon` | SupCon pretraining (20 epochs, temperature 0.1, 128-d projection head), then encoder frozen and a linear head trained with the default recipe |

Validation loss is always plain BCE, and checkpoint selection follows ADR-012 for every arm.

## Pre-registered decision (applied by the kit)

- A component **improves** if its paired DeLong p-value against `default` (pooled seed-averaged
  OOF predictions), Holm-corrected over the 8 components, is < 0.05 **and** the paired
  bootstrap CI of its AUROC gain (2,000 resamples) excludes 0 with a positive gain
  (CLAUDE.md §5).
- The recipe combines all improving components. MixUp/CutMix and focal/label smoothing cannot
  be combined; within each pair the larger AUROC gain is kept.
- If two or more components are kept, one extra full-protocol `combo` arm verifies the
  combination. If none improves, the recipe is the default.
- The decision is written to `results/pipeline/e05_decisions.json`; E4 uses its recipe.

## Metrics, tables, figures

As E1. `results/tables/e05_summary.{csv,md}`, `e05_pairwise.md`; ΔAUROC and ΔECE vs default
with CIs (PLAN 3.3).

## Done criterion

All arms complete; decision recorded; ADR fixing the recipe.

---

## Results

135 runs (9 arms × 15) on data v2 in the Phase 3 kit (commit 0d31953), 0 failures. Tables:
`results/tables/e05_summary.{csv,md}`, `e05_pairwise.md` (vs the best pooled AUROC) and
`e05_vs_reference.md` (the pre-registered comparison vs `default`, with ΔAUROC, ΔECE and
Δlog-loss CIs). Kit decision: `results/pipeline/e05_decisions.json`. Exploratory external AUROC:
`results/tables/external_auroc_exploratory.md`.

## Findings

- No component improves pooled AUROC over `default` (every Holm p ≥ 0.566), so the recipe is the
  default and no `combo` arm ran, as pre-registered.
- Calibration got worse, not better, with several components: the ECE-difference CIs are above 0
  for colorjitter, cutmix, focal, mixup, smoothing and supcon (`e05_vs_reference.md`). Only
  hflip and randaugment are indistinguishable from `default` on ECE.
- SupCon has the lowest pooled AUROC of the arms; its AUROC-difference CI vs `default` lies
  below 0, but the Holm-corrected DeLong p does not meet the threshold, so it is not flagged
  "worse" under the protocol.
- External block (descriptive, ADR-005): the trade-off seen in E1/E2 persists; arms with higher
  Split E recall have lower Mendeley specificity (`e05_summary.md`).
