# E08 · Open set: leave one packaging type out

Written before the experiment runs (PLAN 4.5); the Results section is added afterwards.

## Question

Does a detector trained without a packaging type still work on that type, and do one-class
methods (fitted on authentic images only) generalize better than supervised classifiers?

## Hypothesis

Supervised models lose AUROC on the unseen type compared with the same type seen in training.
No directional hypothesis for the one-class methods.

## Qualifying types

PLAN 4.5 requires ≥ 30 development images of the type in both classes. Data v2 development pool
(`data/processed/manifest_v2.csv`, `split == dev`):

| packaging_type | authentic | counterfeit | qualifies |
|---|---|---|---|
| blister | 124 | 105 | yes |
| packaging | 78 | 97 | yes |
| both | 21 | 0 | no |
| other | 123 | 1 | no |

(`e08_open_set.md` regenerates these counts from the manifest.)

## Design

For each held-out type T ∈ {blister, packaging}:
- Training pool = development images whose group contains no image of type T (a near-duplicate
  group spanning types is excluded as a whole, so no group crosses train and test); split into
  train / val / cal (75 / 12.5 / 12.5, grouped, stratified, seed 42).
- Test = every development image of type T.
- Seeds 0, 1, 2 for trained methods.

## Methods

| Method | Description |
|---|---|
| five comparison models | ADR-021, trained on the training pool as in the full protocol |
| PatchCore | `anomalib` (optional extra `[anomaly]`), backbone `wide_resnet50_2`, fitted on the authentic training images only; anomaly score = counterfeit score. API checked against the installed version before use. One fit per T (deterministic). |
| prototype verifier | `models/prototype.py`: L2-normalized frozen DINOv2 ViT-S/14 embeddings; score = mean cosine distance to the k = 5 nearest authentic training embeddings. One fit per T (no training). |

## Metrics

Primary: AUROC on the unseen type (seed-averaged per image, 95% bootstrap CI).
"Seen" reference: the same type's AUROC in the within-source `p4ref` OOF predictions, where the
type was present in training. It exists for the five supervised models only; PatchCore and the
prototype verifier are not run under the 5-fold protocol.
Secondary: AUPRC; sensitivity at 95% specificity.
